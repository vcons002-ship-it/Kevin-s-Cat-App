Cats never trigger a treat — only people roll — but every sighting is tracked here: when, on which camera, and roughly where in the frame. The button flashes when a cat is on camera right now — moving or still — and tapping it pulls up the live feed of the camera that saw it. When more than one room has a cat, the feed rotates between them. A sleeping cat makes no motion, so the app re-checks for a still cat on the schedule above (Always runs the net every frame).

A real-time view of what the detector sees, with boxes drawn around any person (green) or cat (orange) as it recognises them. It streams only while watching and only to browsers with this open, so it costs little — turn Show live feed off on a slow connection.
Smooth feed runs a dedicated capture thread so the video plays at the camera's frame rate instead of stuttering at your scan rate (which is gated by detection speed — heavy on a slow CPU / big model). It costs a little extra CPU and reads the camera continuously; leave it off if you only need the occasional frame. Smoothness is still limited by the camera's actual output rate.

🌙 Cat-presence (VLM)

⚠ This prompt was written for a different model — an unsuitable prompt can cause high false positives (the moondream2 default produced ~100% FP on moondream3). Verify on a few known-empty frames before trusting batch results.

⚠ Cloud mode sends the image off-device to Moondream’s API.

        batch: run the VLM across several images
        

          One query per image (no sweep). Tick “cat present” per image (untick for
          empty-room controls); the summary reports recall on cat frames
          and false-positive rate on no-cat frames, separately.
        

        

          
          
          
          
        

        

        

      


      
      

        escalation: zoom in and look again (find a missed cat)
        

          When the normal look misses a small/distant cat, the ladder zooms in
          where it makes sense — around recent motion, the last sighting, and a
          CPU-predicted next position — and re-checks with YOLO first (free), asking the
          VLM to point (detect) and to confirm only when the cheap rungs fail.
          A bare VLM guess is never trusted without confirmation.
        

        

          
          
          
        

        

          
          
          
          
          
        

        

          
 

          

          

          
          
        

      

      

        A small vision-language model (moondream) reasons about
        the whole frame to answer “is there a cat?” — a different angle from the box
        detectors, good on hard frames they miss and on decoys they false-fire on. The
        full response is shown because the reasoning is the tool: it
        reveals why it answered (e.g. “the round fuzzy object looks like a cat”).
        moondream’s self-reported confidence is meaningless, so instead the answer is a
        majority vote over N passes (its yes/no wobbles run-to-run) and the
        vote ratio (e.g. 4/5) is the honest confidence — split votes are
        flagged “borderline” for review.
        Paste your API key above (stored locally, never logged); it
        authenticates the one-time weight download and cloud inference. Local
        (Moondream 2) needs a supported GPU (CUDA/Ampere or Apple Silicon — no CPU
        path) and keeps frames on the box; cloud (Moondream 3) is the most
        accurate on hard frames but sends the image off-device. It’s an
        occasional evaluation tool, not an every-frame path.

⚙ Setup & settings — saved automatically; set these once


    

      
1. Cameras (watch one or several — each with its own role & settings)

      

        
        
        
        
        
      

      

      

        
        
        
      

      

        Tick Watch on each camera you want running at once. Every camera
        chooses a role — 🎲 Rolls (a person rolls for a treat) and/or
        🐱 Tracks cats (sightings logged) — and has its own detection settings and
        region of interest. CPU: each watched camera adds roughly one camera's
        load, but the neural net only runs when something moves, so idle cameras are cheap.
        
⟳ Round-robin caps that: only a few cameras detect at a time and
        the app rotates through the rest on an interval, so many cameras cost about as much as a
        few (the trade-off is a slower reaction on whichever cameras are currently resting 💤).
        Mark a camera 👁 always-watch to keep it from ever resting (e.g. the
        treat camera); the camera you're viewing live never rests either.
        Credentials are stored locally in config.yaml in plain text.

2. Speaker(s) (where the chime plays)

      
      

        
        
      

      

      

        Found automatically over WiFi (Google Cast — no account or login needed).
        Pick one or more — Ctrl/Cmd-click (or drag) to select several and the
        treat plays on all of them. This device and the speakers must be on the same
        WiFi network. Names match your Google Home app. Connections are kept open so
        there's no "connecting" chime each time. The first option, "This PC (local
        audio)", plays the sound on this computer's own speakers (handy on a laptop/desktop;
        needs the optional local-audio support from setup) — you can pick it, a Cast device, or both.
      

      
      Loops a silent clip every couple of minutes so the Cast receiver never unloads — the only thing that actually stops the chime on a Google Home. Trade-off: it holds the speaker active and briefly yields to (won't stomp on) other audio. Leave off if you use these speakers for music.
